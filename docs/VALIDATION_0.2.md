# rdrive 0.2.0 验证记录

日期：2026-11-09。环境：macOS 27.2、Apple Silicon arm64、Rust/Cargo 1.90.0。

本次所有服务端测试使用本机临时 WebDAV 服务或隔离 Samba 容器，数据与账户均为合成测试内容。没有连接真实 NAS、云盘或其他人的存储。原生挂载测试实际调用了 macOS 网络文件系统，测试挂载和临时容器均已清理，没有启用 macOS 文件共享、修改真实服务器或写入钥匙串凭据。

## 常规测试

最终代码的 `cargo test --locked --offline` 通过 **76 项测试**：

- 48 项库测试，包括路径、持久化、19 项同步回归、12 项挂载模块和 6 项下载检查点测试。
- 3 项公开挂载 API 测试。
- 25 项 WebDAV HTTP 协议测试。

另外三个要求本机挂载权限或 Samba 服务的测试在普通测试中明确标记为 ignored，随后单独实际运行通过；没有删除或弱化断言来通过测试。

下载检查点测试验证断线后按原偏移继续、进程任务取消后仍有落盘检查点、未保存尾部被丢弃、已保存前缀损坏时拒绝请求、远端版本变化时停止、本地编辑不被覆盖，以及提交完成但清理前中断的恢复。

同步回归还验证 0.1 的弱 SMB 基线只有在远端内容哈希与旧本地基线一致时才升级；未完成 SMB 恢复收据会阻止 `--delete` 把发布期间的路径空缺推断成用户删除。

## 真实原生挂载

开发构建的实际 macOS 挂载检查通过：

- WebDAV：带认证的本机服务；密码通过已取消文件名的文件描述符传给系统程序；验证内核挂载表、读取合成文件、只读写入拒绝、正常卸载及挂载消失。
- SMB：隔离加密 Samba；密码通过终端输入，不进入参数；挂载连接 URL 中的子目录，验证共享根目录其他文件没有暴露、只读写入拒绝，并用 `smbutil` 观察到实际 AES 加密。
- SMB 可写挂载：写入已到达服务端共享目录，再进行重命名和删除，随后正常卸载并验证消失。

受限执行环境最初阻止本机端口监听和挂载；允许本机测试后成功。没有通过修改系统安全设置绕过限制。

WebDAV 可写原生挂载取决于系统客户端及服务端 DAV LOCK 支持，本次真实 WebDAV 挂载验证的是只读模式。SMB 原生只读和可写模式均已实测。更多说明见 [MOUNT.md](MOUNT.md)。

## 发布版命令行流程

最终 `target/release/rdrive` 输出版本 **0.2.0**，两个协议分别通过 9 组命令行工作流。

WebDAV 检查涵盖 2 MiB 二进制与中文路径传输、默认不覆盖、`cat`、上传独立快照、失败保留、状态不明的覆盖不会自动重试、离线缓存/固定/清理、版本保存与损坏拒绝、复制/移动/删除、WebDAV 锁、同步计划/应用/两端冲突以及密码不落盘。

新增的真实 HTTP 断线检查让服务器在发送一半数据后断开：第一条 `get --resume` 失败并保存检查点，目标文件尚未出现；第二个独立 CLI 进程实际发送非零 Range，仅请求缺少的一半，最终内容和 SHA-256 正确。远端随后改变时，不再发送续传请求，不创建或覆盖本地目标。

SMB 使用 Samba **4.21.9**，强制 SMB3 传输加密，发布版检查涵盖 2,304,256 字节多块上传/下载字节核对、stat/list、复制/重命名不覆盖、完整临时文件发布、文件及递归目录删除、新文件同步、已有文件的受保护同步覆盖、恢复文件过滤，以及 CLI `put/get --resume`。

## SMB 并发与断线恢复证明

两个单独运行的真实 Samba 后端测试通过，包含：

- 远端同大小修改并恢复原修改时间后，旧修订覆盖仍被 SHA-256 检出并拒绝。
- 另一个独立 SMB 客户端在旧文件保护句柄持有期间发起 WRITE/DELETE，服务器返回 SharingViolation。
- 使用同一持有 DELETE 权限的受保护句柄，把旧文件移到恢复备份可行。
- 新文件发布的路径空缺期间，另一客户端创建同名目标：发布因禁止覆盖而失败，对方文件保留，旧副本与新临时文件也保留。
- 上传在落盘 1 MiB 检查点后中断；即使本地记录偏移故意滞后，恢复也核对真实服务器前缀，并从服务器实际非零长度继续，首个新增写入位置为 1 MiB。
- 下载从 65,549 字节已有前缀继续；损坏的本地或远端前缀均被拒绝。
- 发布成功但回执丢失时，按暂存文件身份核对完成结果；内容相同但身份不同的外来目标不能冒充本次上传。
- 旧文件移到备份后中断：同步检查对未完成收据停止，显式上传检查点恢复后发布成功，旧备份仍存在。
- 收据检查保持只读；成功标记绑定收据内容哈希和发布文件身份，真实的后续用户删除不会被旧成功收据阻塞。

覆盖过程先保护并验证旧文件，再移动到备份并以禁止覆盖的重命名发布新文件。两次重命名之间存在路径空缺，不是跨崩溃的原子事务。服务器本地进程、NFS 等绕开 SMB 共享规则的写入不受这些 SMB 句柄保护。SMB 条件删除仍未实现，自动远端删除保持拒绝。

Samba 默认透明解析 POSIX 符号链接时，客户端无法识别链接身份；实际 stat/读取会得到目标内容。另一个临时服务端策略检查设置 `follow symlinks = no` 后，普通文件仍可读，链接访问被服务器阻止。这不能描述为客户端普遍支持远端 lstat/no-follow。

## Nextcloud 上传续传

25 项 WebDAV 测试中包含明确启用 Nextcloud v2 上传端点的本地协议服务，使用实际 5 MiB 数据块加尾块验证：

- 中断后，已经确认且强校验标识未变的第一块不再 PUT，只重传未确认的尾块。
- 无可靠校验标识的块会单独重传，不能只凭大小复用。
- 源文件改变或会话元数据指向显式端点之外时拒绝继续。
- 最终 MOVE 使用目标条件保护；412 冲突不会变成无条件覆盖。
- 发布后通过完整 GET 核对源 SHA-256。发布结果不明时只核对完成目标，不盲目重发 MOVE。

普通 WebDAV 上传没有通用分段续传协议，本程序没有发送猜测性的部分 PUT。真实 Nextcloud 服务器兼容性、分块过期、真实 NAS、长期弱网和多厂商性能均未实测。

## 依赖与复现

SMB 依赖有最小本地补丁，增加可选的 ShareAccess 参数，默认保持上游行为，以获得服务器拒写/删句柄。上游 MIT 许可证、精确版本/提交与补丁说明见 [RDRIVE-PATCH.md](../vendor/smb/RDRIVE-PATCH.md)。没有修改其加密、认证或协议实现。构建会出现上游一条 async 配置下的 unused-import 警告，不影响测试或执行。

本次使用项目命令参数选择 rsproxy 镜像，Cargo.lock 固定依赖版本及校验和，没有修改全局 Cargo 或网络设置。普通环境可使用：

```sh
cargo build --release --locked
cargo test --locked
python3 tests/cli_workflows.py target/release/rdrive
python3 tests/smb_workflows.py target/release/rdrive
python3 tests/mount_workflows.py target/release/rdrive
cargo test --test mount native_webdav_readonly_roundtrip -- --ignored --nocapture
```

SMB/原生 SMB 集成 fixture 需要 Docker，产品本身不需要 Docker 或 Samba 安装。两个 SMB 后端故障测试的复现方式见 `tests/smb_workflows.py` 中 `RDRIVE_SMB_TEST_RUNNER` 参数；它们需要在同一临时 Samba 会话内运行。

本次离线构建/测试前缀为：

```sh
cargo --config 'source.crates-io.replace-with="rsproxy"' \
  --config 'source.rsproxy.registry="sparse+https://rsproxy.cn/index/"' \
  test --locked --offline
```
