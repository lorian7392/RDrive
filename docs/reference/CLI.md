# Complete CLI reference

This file is generated by recursively reading the current executable's `--help`
with `scripts/generate-cli-docs.py`. Each entry includes its complete usage,
positional arguments, short and long options, defaults, accepted values, and
inherited global options. Regenerate it after changing the CLI, then use
`--check` to detect differences between the documentation and actual help.

```sh
cargo build --locked
python3 scripts/generate-cli-docs.py --binary target/debug/rdrive
python3 scripts/generate-cli-docs.py --binary target/debug/rdrive --check
```

Generation invokes only `--help` and `--version`. It does not create a state
directory, read credentials, or connect to a server. `rdrive help COMMAND
[SUBCOMMAND]` is equivalent to the corresponding `--help`; Clap provides it
automatically, so it is not expanded again below. Trailing arguments to
`provider native` are passed to the optional native companion. See
[macOS integration](../MACOS_INTEGRATION.md) for that application's setup.

## Conventions

- `<NAME>` is required; `[NAME]` is optional; `...` means the value can repeat.
- `PROFILE` is an existing connection name; `DOMAIN` is an existing File Provider
  or Smart domain ID. Use the identifiers returned by the relevant creation or
  listing commands for `TRANSACTION`, `MUTATION`, and `ID`.
- `REMOTE`, `ROOT`, and remote `PATH`, `FROM`, and `TO` are relative to the
  connection or repository root; an empty string denotes that root. Use `/` as
  the separator. Leading `/`, `..`, backslashes, and NUL are rejected; repeated
  `/` and `.` components are normalized. `LOCAL`, `RECORD`, `JOURNAL`, `STAGING`,
  and similar local arguments are filesystem paths on this computer.
- Sizes, capacities, and rates use bytes; time arguments use seconds. Quote
  paths and globs containing spaces, `*`, or other shell metacharacters. Boolean
  switches take the option name alone, without an additional `true` value.
- Structured results use indented JSON by default; `--json` selects compact,
  single-line JSON. Errors usually go to stderr. `cat` writes raw bytes to
  stdout, `notify` writes newline-delimited JSON events, and MCP stdio uses
  JSON-RPC. Progress goes to stderr. Failed operations return a nonzero status;
  invalid arguments or rate limits can fail before execution starts.

## Global options and execution constraints

- State selection follows `--home PATH`, then `RDRIVE_HOME`, then the optional
  private `~/Library/Application Support/rdrive/shared-home.json` reference,
  then `~/Library/Application Support/rdrive`. The reference points to an
  existing Finder state directory; it contains no profiles or credentials.
- `--json` changes structured results and the usual runtime-error format; it
  does not change file-content encoding.
- `--limit BYTES_PER_SECOND` is a positive integer payload-rate limit shared by
  all transfers in the same Rust process. `0` is rejected. Protocol headers,
  encryption, and TCP retransmissions are outside this accounting; the limit
  does not control macOS native-volume I/O.
- `--progress auto|off|json` defaults to `auto`: a terminal gets a progress bar,
  while redirected output gets JSON events. `json` always uses JSON; `off`
  disables progress. Speed is calculated over the preceding two seconds.
- `--jobs N` sets the queue concurrency target, defaults to `4`, and must be
  `1..=64` when running a queue. Jobs for the same connection and path retain
  their order; this does not parallelize every command automatically.
- `-h, --help` shows help for the current entry. At the root, `-V, --version`
  shows the program version.

`history --limit N` is a **record count**, defaults to `20`, and overrides that
entry's inherited option with the same name. Do not use it to set transfer speed.

## Validation beyond command help

These requirements come from runtime validation. The help blocks below also
list every positional argument and option.

- `profile add` requires `--protocol` and `--url`; the protocol is `webdav|smb`.
  Connection names contain only ASCII letters, digits, `-`, and `_`, cannot be
  empty, and cannot start with `-`. `--timeout` defaults to `120` and must be
  greater than `0`. WebDAV requires HTTPS unless `--allow-http` is given. SMB
  requires encryption unless `--allow-unencrypted-smb` explicitly disables it.
  URLs cannot contain credentials, queries, or fragments. `--nextcloud-upload-url`
  applies only to same-origin WebDAV. `--keychain-internet` reads an existing
  macOS Internet Keychain item for the URL host and username; it cannot be
  combined with `--password-env`. See [Configuration](CONFIGURATION.md) for
  credential handling.
- `get`, `cache get`, `repo get`, and `smart export` preserve existing local
  files by default; `put`, `cp`, and `mv` preserve existing remote destinations.
  Replacement requires the applicable `--overwrite` option. `put --queue` only
  saves a durable snapshot and job; `--resume` requires protocol support.
  `cat --max-bytes N` rejects oversized files before downloading them.
- Deleting a directory requires `rm --recursive`; the root cannot be deleted.
  Creating missing ancestors requires `mkdir --parents`. `sync` and `versions
  prune` preview their plans until `--apply` is supplied. `cache clear` also
  requires `--apply` to remove content.
- `sync` / `watch --direction` accepts `push|pull|both`, defaulting to `both`.
  `--delete` propagates observed deletions only after a successful baseline;
  `--metadata` synchronizes selected attributes. `watch --interval` defaults to
  `30` and must be greater than `0`.
- `update` checks GitHub Releases. `--apply` installs the newer standalone CLI
  after verifying the release checksum.
- `conflict repair --choose local|remote` previews the selected file repair.
  `--apply` and `--expect TOKEN` must be used together. The displaced content
  stays under `.rdrive-versions/` within the local sync root.
- `smart refresh-conflict DOMAIN MUTATION` refreshes the parent of an eligible
  stale Finder directory request and cancels that request locally.
- `cache config` requires either `--max-bytes N` or `--unlimited`, never both.
  `cache directory PATH` conflicts with `--default`; omitting both queries the
  current directory. `--dry-run` previews migration. `cache prune --max-bytes`
  defaults to `0` and still protects pinned content and active readers.
- `index config --enable` conflicts with `--disable`; `--depth` conflicts with
  `--all`. Both refresh intervals must be `1..=31536000`. `index search --kind`
  accepts `file|directory`. `--page-size` defaults to `100` and must be `1..=1000`;
  `--offset` defaults to `0` and cannot exceed `1000000`. After trimming, the
  query must contain `1..=512` printable characters. Search scope is relative
  to the domain root.
- `filter config --exclude-temporary` conflicts with `--include-temporary`.
  `--clear-include` conflicts with `--include`; `--clear-exclude` conflicts with
  `--exclude`. Repeat `--include` or `--exclude` to replace the entire supplied
  list; omitted lists retain their values. `--profile` changes only that
  connection; `filter reset PROFILE` removes its override.
- `policy config --enable-versions` conflicts with `--disable-versions`; each
  `--clear-*` option conflicts with its corresponding list. `--keep` must be
  `1..=100000`; conflict strategies are `stop|keep-both|replace`. See
  [Configuration](CONFIGURATION.md) for rules, inheritance, and defaults.
- `smart setup --app` requires `--register`; setup does not register native
  extensions by default. `smart resolve --strategy` is required and accepts
  `keep-both|replace|remote`. Omitting the mutation in `smart retry` retries the
  domain's retryable retained work. `smart cancel` preserves recovery snapshots;
  `smart discard` removes recovery snapshots only for completed work.
- `mcp serve --timeout` defaults to `300` and must be greater than `0`.
  `--local-root` can repeat. Write tools require `--allow-write`; local reads
  and writes remain restricted to authorized roots. Inspect tool arguments
  with `mcp tools [--allow-write]`; see [MCP](../MCP.md).
- `queue run --retry-failed` explicitly retries failed jobs. An unconditional
  overwrite with an uncertain result additionally requires
  `--retry-ambiguous-overwrite`. `transfers discard` removes only a download
  checkpoint and preserves existing local recovery copies.
- `mount` requires an existing, empty, current-user-owned private directory
  with mode `0700`; `--dry-run` generates only a plan. `--browse` permits the
  system to display the volume; `--no-prompt` uses only existing system
  credentials; `--read-only` requests an actual read-only volume.
  `unmount --force` uses the system's forced-unmount option.
- `provider serve` requires `--socket` and `--staging`; `--development-tcp` is
  only for a matching development package. `service install` installs user
  service configuration without starting it; use `service start` to run it.
  Saved paths and the development IPC mode must match the App being used.
- `lock --seconds` defaults to `600`; the WebDAV server decides the actual
  duration, and RDrive does not renew it automatically. Mutations and `unlock`
  read the token from `RDRIVE_WEBDAV_LOCK_TOKEN`; there is no token argument.

See [Features](../FEATURES.md) for conditional writes, recovery copies, protocol
capabilities, and limitations.

## Optional native companion options

`provider native [--app /absolute/path/RDrive.app] -- ARGS...` passes trailing
arguments unchanged to `Contents/MacOS/RDriveCompanion`; this is not another
Clap command group. Without `--app`, it uses `macos/build/RDrive.app` under the
source directory recorded when the CLI was compiled. Specify the App explicitly
after moving an installation. Without ARGS, it starts the menu-bar App and
reports process launch, not successful server authentication or registration.

The native program has no general `--help`. The following complete control
option list comes from `macos/Companion/main.swift`; documentation generation
does not execute these system operations. Select one operation per invocation
to avoid relying on implementation-branch precedence between multiple actions.

- `--group-directory PATH` overrides the companion's development IPC/group
  directory. It must be an existing absolute private directory owned by the
  current user. Normally use the matching path embedded in the build; this
  option does not rewrite extension configuration automatically.
- `--diagnose` reports bundle details, Finder-extension settings, and group
  paths/errors; it is not a connection test.
- `--list-domains` queries macOS-registered File Provider domains.
- `--register-domain DOMAIN [--display-name NAME]` registers a domain with the
  system. The display name defaults to its ID; first create the corresponding
  local RDrive domain configuration.
- `--remove-domain DOMAIN` asks the system to remove a domain while preserving
  downloaded user data, and reports the retained-data location.
- `--domain-root DOMAIN` queries the domain's user-visible root path.
- `--resolve-file PATH` resolves a system-visible file path to a domain and item ID.
- `--signal DOMAIN` requests a working-set enumerator refresh.
- `--retry-sync DOMAIN` asks macOS to retry requests held by connection or synchronization errors in the registered domain, preserving RDrive's original queue and revision checks.
- `--download DOMAIN ITEM_ID` requests system content download; it does not
  change the offline-pinning policy.
- `--evict DOMAIN ITEM_ID` requests system eviction, subject to system protection
  for pinned, active, and not-yet-uploaded content.
- `--pin DOMAIN ITEM_ID` / `--unpin DOMAIN ITEM_ID` checks capacity and sets or
  clears pinning through the bridge and system content policy. Unpinning does
  not guarantee immediate eviction.
- `--check-cache DOMAIN ITEM_ID` checks capacity and releases its temporary
  reservation without pinning or downloading content.
- `--trim-cache BYTES` requests removal of evictable system clean copies and
  accepts a nonnegative integer. It neither saves `cache.max_bytes` nor moves
  the system directory.
- `--set-tags PATH [TAG...]` sets tags through the standard macOS URL-resource
  `tagNames` interface; no TAG clears them. Every argument after PATH is treated
  as a tag name, so do not append other options afterward.
- `--watch-domains` runs the native change-notification helper in the foreground,
  polling approximately every three seconds; SIGINT/SIGTERM stops it.
- `--enable-finder` opens system extension settings; the user must still enable
  the extension in the system interface.
- `--show-status DOMAIN ITEM_ID` starts the menu-bar App and opens item status.
- `--show-message TEXT` starts the menu-bar App and displays a message dialog.

Except for persistent notifications and GUI operation, asynchronous system
controls generally wait up to 30 seconds. A timeout does not cancel the system
operation. GUI startup can manage the bridge and is not a side-effect-free help
command. See [macOS integration](../MACOS_INTEGRATION.md) for platform, signing,
enablement, and actual validation scope.
